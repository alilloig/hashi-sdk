## What Was Fixed (commit a02391f)

### 1. `deriveDepositAddress()` — was a stub, now fully implemented
**File**: `src/bitcoin.ts`

The stub that threw "not yet implemented" now implements the full derivation:
- HKDF-SHA3-256 tweak from `x(mpcKey) || suiAddress`
- secp256k1 point addition: `mpcKey + tweakScalar * G`
- P2TR script-path address with NUMS internal key + `<xOnly> OP_CHECKSIG` leaf

Also added `arkworksToCompressedHex()` to convert on-chain MPC keys (ark-works LE format) to standard Bitcoin compressed pubkey format (02/03 prefix + BE x).

**Usage**:
```typescript
import { deriveDepositAddress, arkworksToCompressedHex } from 'hashi-sdk/bitcoin';

// 1. Get MPC key from on-chain Hashi object (ark-works format, 33 bytes)
const mpcKeyBytes = /* fetch from committee_set.mpc_public_key */;

// 2. Convert to standard compressed format
const mpcPubkeyHex = arkworksToCompressedHex(mpcKeyBytes);

// 3. Derive deposit address
const btcAddress = deriveDepositAddress(mpcPubkeyHex, suiAddress, 'testnet');
// Returns: tb1p... (signet/testnet P2TR address)
```

### 2. Deposit fee — was hardcoded to 0, now parameterized
**File**: `src/transactions/createDepositRequest.ts`

`CreateDepositRequestParams` now accepts optional `depositFee` (defaults to `0n`).

New `getDepositFee()` method on `HashiClient` fetches the current fee from on-chain config.

### 3. Bitcoin network — signet, not testnet4
The Hashi devnet uses Bitcoin **signet**. Dashboard faucet link updated accordingly.

## Key Insight for Your Integration

The deposit flow REQUIRES:
1. Derive the correct Bitcoin deposit address from MPC key + Sui address
2. Send BTC to THAT specific address
3. Submit deposit request with matching txid, vout, exact amount, and derivation_path

If the BTC is sent to any other address, validators will reject with `NeverRetry` — exactly the error you saw. The `deriveDepositAddress()` function is now available to compute the correct address.

## Root Causes of the Original Failure

From on-chain transaction comparison:
- **Amount mismatch**: SDK deposit claimed 100M sats but actual UTXO value didn't match what committee expected
- **Address mismatch**: BTC was sent to a random address, not the one derived from MPC key + derivation_path
- **Fee hardcoding**: Would have broken when governance sets deposit_fee > 0 (latent bug, now fixed)
